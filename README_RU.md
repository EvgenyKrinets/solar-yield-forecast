# Solar Yield Forecast — руководство по установке

## 0.7.0 — intraday calibration / обучение формы

The integration now learns the intraday profile from seven days of local DC
power history. Corrections are enabled only after improving a separate
two-day retrospective validation by at least 10%; insufficient data leaves
the base forecast active. The hourly correction uses UTC to avoid DST shifts.
It is combined with the existing daily calibration, and applied to interval
energy as well as the power curve. Model Today exposes the modeled whole-day
energy separately from Today (actual plus remaining).

Поправки формы обучаются по истории DC-мощности автоматически. Статус,
ошибки проверки и коэффициенты доступны в свойствах Today. Это проверка
модели на прошлой погоде, а не обещание такой же точности на завтра.
Для обновления установите 0.7.0 через HACS и перезапустите Home Assistant.

## 0.6.0

15-minute time-weighted analysis replaces sample-count averaging. Only fully covered, completed intervals are shown. Open-Meteo 15-minute forecasts are integrated as kW × 0.25 h, with hourly fallback for the remaining horizon. In Israel, the provider interpolates weather from hourly data; this is not a guarantee of 15-minute weather accuracy. See [release notes](RELEASE_NOTES.md).

Установка: нажмите **Open in HACS**, подтвердите добавление репозитория и скачайте интеграцию. Перезапустите Home Assistant и добавьте Solar Yield Forecast в Devices & services. Карточки устанавливаются автоматически: выберите широкую или компактную в редакторе нужного Dashboard. Первую установку и перезапуск подтверждает пользователь; интеграция не устанавливает HACS самостоятельно.

В 0.6.0 фактическая мощность учитывает длительность показаний, пропуски не соединяются линией. Показываются завершённые 15-минутные интервалы. Новые данные прогноза используют длительность интервала при расчёте энергии. Погодная точность для Израиля ограничена интерполяцией Open-Meteo. Раздел о 0.5.0 ниже описывает предыдущую версию.


Интеграция Home Assistant для системы 48 × 670 Вт = 32,16 кВтp в пяти группах. Использует Open-Meteo, корректирует прогноз по реальной суточной энергии и ведёт независимую оценку ошибки прогнозов на будущие дни.

## HACS (настройка один раз)

1. Открой HACS → меню → Custom repositories.
2. Добавь `https://github.com/EvgenyKrinets/solar-yield-forecast` и выбери тип **Integration**.
3. Установи **Solar Yield Forecast** и перезапусти Home Assistant.
4. Settings → Devices & services → Add integration → **Solar Yield Forecast**.
5. Проверь широту, долготу и датчики:
   - `sensor.daily_pv_generation` — энергия за сутки в кВт·ч;
   - `sensor.total_dc_power` — текущая мощность PV (Вт).

После подключения интеграция загружает погоду по каждой из пяти ориентаций и показывает прогноз на сегодня, завтра, 7 дней, почасовой профиль и метрики калибровки.

**Начиная с версии 0.4.0 карточка включена в интеграцию и загружается автоматически.** Не нужно скачивать JavaScript в `/config/www/` или добавлять его в Dashboard Resources. После установки/обновления через HACS перезапусти Home Assistant и обнови браузер. Добавь карточку вручную из `dashboard.yaml` или выбери Solar Comparison Card в редакторе карточек.

## Достоверность прогноза

- `Training Error` — ошибка подгонки на исторических днях, **не** точность будущего прогноза.
- `Forward Forecast Error` — ошибка сохранённых прогнозов, выпущенных минимум за день до даты. В начале она может быть недоступна до накопления наблюдений.
- В течение дня прогноз `Today` меняется: фактически произведённая энергия + погодная оценка оставшегося дня.
- Мощность `Power Now` — средняя за интервал (15 минут при наличии данных, иначе час), а не мгновенное измерение.
- Долговременные ограничения экспорта и заряда могут привести к недоучёту потенциальной генерации.

## Широкий график на 3 колонки

Используй **Sections** dashboard, а не Masonry. В редакторе Dashboard настрой максимальное число колонок минимум 3 и создай секцию с **Column span = 3** (если доступно в твоей версии интерфейса). Добавь Solar Comparison Card в эту секцию, в её настройках выбери **Full width card**. В YAML карточки предусмотрено `grid_options: {columns: full, rows: 8}`. При узком экране секция адаптивно занимает всю доступную ширину. В Masonry отдельная карточка не умеет занимать три стандартные колонки. Если ранее был добавлен ручной ресурс `/local/solar-comparison-card.js`, удали его в Dashboard Resources, чтобы не загружать старый вариант параллельно.

## Обновление с v0.3.0 на v0.4.0

Обнови интеграцию в HACS, перезапусти HA, очисти кэш страницы один раз (Ctrl+Shift+R). Сохрани существующую config entry: при удалении интеграции можно лишиться сохранённых параметров.

## Выбор большой или маленькой карточки (v0.4.1)

При добавлении карточки из интерфейса Dashboard выбери **Solar Comparison — широкий** (тип `custom:solar-comparison-card`) или **Solar Comparison — компактный** (тип `custom:solar-comparison-compact`). Обе загружаются автоматически вместе с интеграцией. Добавляй на нужный Dashboard и перетаскивай в выбранную секцию; Home Assistant определяет её расположение, интеграция не может произвольно переставлять карточки во всех Dashboard. В Sections широкая карточка занимает полную ширину секции; компактная — около шести ячеек сетки. Чтобы сделать широкой на три колонки, задай секции `Column span = 3`. После обновления перезапусти HA и обнови страницу.

## Версия 0.5.0: наведение и 15-минутный анализ

В графике можно навести мышку или коснуться линии, чтобы увидеть мощность **вчера, сегодня и по прогнозу** для выбранного времени. Фактические данные Sungrow усредняются по 15-минутным корзинам. Прогнозный профиль теперь содержит 96 точек в сутки: **это интерполяция почасового погодного прогноза**, а не новая независимая оценка погоды на каждую четверть часа. В Израиле прогноз GTI Open-Meteo за 15 минут может быть получен интерполяцией часовых данных. Внутренняя оценка прогнозной энергии пересчитывается каждые 15 минут при доступном API. Суточная энергия при этом считается по исходным часовым средним, чтобы не возникала искусственная точность. Установи обновление через HACS, перезапусти Home Assistant и обнови браузер.

## Проверка точности

[Разбор расхождений и источников погоды](FORECAST_ACCURACY.md). Для подтверждения причины ошибки требуется история датчиков. Установка через HACS работает как custom repository; заявка в общий каталог HACS не подавалась. Проверки описания и topics в CI исключены только для этого режима.

## Плавные графики (0.7.1)

Линии проходят через исходные 15-минутные точки без искусственных пиков и соединений через пропуски. Сглаживание меняет только рисунок, а не значения в подсказках или расчёт энергии. Для прямых отрезков добавь `smooth: false` в YAML карточки. Используется шрифт Home Assistant/системы; в узкой карточке дневные столбцы расположены в два ряда.

## 0.8.0 — Управление графиком

Периоды: День, Неделя, Месяц, Год и Всё время. Стрелки переключают выбранный период; дата открывает календарь. Двумя пальцами увеличивайте график дня, затем перемещайте его пальцем. «Сбросить Zoom» возвращает сутки целиком; на компьютере доступен Ctrl + колесо. Кнопка ⛶ разворачивает карточку. Переключатели скрывают и показывают линии.

За день показана мощность, за большие периоды — энергия. Нажатие столбца открывает месяц или день. Старые графики доступны в пределах хранения Recorder. Итоги используют сохранённые интеграцией дневные значения; отсутствующие дни не считаются нулевыми, неполные периоды отмечены. Почасовой прогноз доступен для сегодня/завтра; на остальные дни остаётся прогноз суточной энергии. После обновления нужен перезапуск Home Assistant.
